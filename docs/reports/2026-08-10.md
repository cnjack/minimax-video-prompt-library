## Risks

- **Reporting-cadence coverage gap (new, this report).** Two default-branch
  commits — `5104b10` (the prior weekly report itself, 2026-08-01T00:02:10Z) and
  `79b87ec`/PR #15 (2026-08-01T05:36:51Z) — fall between the previous report's
  window (2026-07-24 → 2026-07-31) and this one (2026-08-03 → 2026-08-10). Their
  substance is already recorded (`CHANGELOG.md` `[Unreleased]` + the `2026-07-31`
  report), so nothing is lost, but the gap shows that an ad-hoc weekly cadence
  can let a day or two slip between windows. A fixed, recurring steward run would
  prevent this.
- **Unreleased backlog accumulating.** Substantial, user-visible work has been
  sitting under `[Unreleased]` in `CHANGELOG.md` since 2026-08-01 without a
  tagged release: the provider rewrite to `MiniMax-Hailuo-2.3`, the
  Hailuo-2.3 constraints, the paid-job read-path resilience (P1), and the
  `tracking_exhausted` + Resume recovery model. None of this has been promoted to
  a versioned release yet.
- **Exactly-once boundary (documented, pre-existing).** The single-instance PoC
  stores a job row before submitting to the provider; if interrupted after the
  provider accepted but before the task id persisted, the provider may have
  started a generation the local row does not know about. Startup recovery
  mitigates, but does not eliminate, this gap.
- **Single-instance polling (pre-existing).** No durable queue, horizontal
  multi-instance polling, or webhooks; acceptable for the PoC, not for prod
  scale.
- **SSRF / media safety (pre-existing).** External media URLs are validated as
  `http(s)` only; URL allowlists and server-side media ingestion remain a
  documented extension point.
- **Mutable image tag (pre-existing).** The committed `:latest` Docker tag is a
  local convenience; production should pin an immutable tag or digest.

## Follow-ups

- **Cut a versioned release** (e.g. `1.1.0`) to formally ship the `[Unreleased]`
  backlog (Hailuo-2.3 provider rewrite, request constraints, paid-job
  read-path resilience, `tracking_exhausted` + Resume), which has been unreleased
  since 2026-08-01.
- **Adopt a fixed weekly reporting cadence** (and/or generate the report from the
  same scheduled run) so no day falls between consecutive windows, as 2026-08-01
  → 2026-08-03 did here.
- Close the exactly-once gap with a **durable outbox plus provider-side
  idempotency** (the documented extension point).
- Replace the in-process poller with a **distributed queue** and add **webhooks**;
  support **horizontal multi-instance** polling.
- Implement **SSRF allowlists / media scanning** before provider fetches.
- Pin an **immutable image digest/tag** for the Kubernetes Deployment instead of
  `:latest`.
